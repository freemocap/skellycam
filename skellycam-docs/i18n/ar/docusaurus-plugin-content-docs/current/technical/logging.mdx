# التسجيل

## المراقبة هي المفتاح!

SkellyCam نظام معقد متعدد العمليات — كل كاميرا بتشتغل بعمليتها الخاصة، بتتواصل عبر الذاكرة المشتركة وقنوات IPC. لما يصير شي غلط (أو لما بس بدك تفهم شو عم يصير تحت الغطاء)، التسجيل الجيد ضروري. المراقبة هي المفتاح لفهم سلوك نظام ما فيك تمشي فيه بسهولة بمنقّح الأخطاء.

## الإعدادات

SkellyCam بيستخدم [skellylogs](https://github.com/freemocap/skellylogs) للتسجيل، اللي بيوفر مستويات تسجيل مخصصة وتحويل السجلات عبر WebSocket. مستوى التسجيل بيتحط بـ `skellycam/__init__.py`:

```python
LOG_LEVEL = LogLevels.TRACE  # Change to LogLevels.INFO for less verbose output
```

السجلات بمستوى `TRACE` وفوق بتتحوّل لعملاء WebSocket المتصلين للعرض بطرفية السجلات بالواجهة.

ملفات السجلات بتتحفظ بـ `~/skellycam_data/logs_info_and_settings/logs/`.

## عارض السجلات بالواجهة

واجهة SkellyCam بتتضمن طرفية سجلات بتعكس سجلات السيرفر الخلفي بالوقت الحقيقي. بس هاد بس بيشتغل لما السيرفر بحالة سليمة واتصال WebSocket نشط — وهاد كتير أوقات مش الوضع لما أكتر شي بتحتاج تشوف السجلات.

:::tip أقصى مراقبة
لأقصى مراقبة، حط **الاتصال التلقائي** على `false` بإعدادات الواجهة وشغّل سيرفر SkellyCam بنافذة طرفية خاصة فيه. هيك فيك تشوف سجلات السيرفر الخام حتى لو الواجهة ما قدرت تتصل أو إذا السيرفر فشل قبل ما يبعت السجلات المهمة للواجهة.
:::

## مشاركة السجلات

طرفية السجلات بالواجهة بتتضمن أزرار **نسخ للحافظة** و **حفظ على القرص**. هدول مفيدين لما تطلب مساعدة على [سيرفر Discord](https://discord.gg/SgdnzbHDTG) أو لما تفتح [مشاكل GitHub](https://github.com/freemocap/skellycam/issues). تضمين سجلاتك بيسهّل كتير على غيرك يشخّصوا المشكلة.

شوف صفحة [المجتمع](/docs/community) لطرق أكتر للمشاركة والحصول على مساعدة.
